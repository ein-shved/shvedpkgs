modules/nixos.nix, pkgs, external agenix/vim/home-manager/niri-flake/
nix-index-database/nixos-generators/disko modules, and agenix/niri overlays.
mkSystem passes project lib, flake-inputs, and pkgsUnstable through specialArgs.
lib/system.nix mkExtendableSystems accumulates modules and specialArgs through
extend, creates nixosConfigurations and nixosValidationConfigurations, and
exposes host package sets via transformNixosPackages.
Validation modules default to tests/modules/stubs/private-values, separately
from deployable configurations. Do not silently include validation secrets or
host-specific configuration in every test.

lib/modules.nix mkBynameOverlayModule adds the local by-name packages and a
pkgsOrigin reference to the original package set. Inspect this existing escape
route when considering a testers override and avoiding recursive dependencies.

## Design questions for the next phase

- Define exactly which modules tests gain: reusable project modules, external
  modules, opinionated config policy, and extension modules from .extend.
  User requested all modules available in the project, but did not explicitly
  decide whether all policy must be activated in every node.
- Establish inherited specialArgs and package-set/overlay semantics and caller
  override precedence without recursion.
- Determine whether testers.runNixOSTest can be extended compatibly or a separate
  project-aware helper is needed. Existing function is preferred, not mandatory.
- Define compatibility checks for ordinary upstream package tests and specd VM
  tests; preserve minimal tests and prevent unrelated service/private inputs.
- Define public validation and VM execution evidence given cloud limitations.
