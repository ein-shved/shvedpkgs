# Delegated design coordinator

Load this only after explicit delegated participation. The main session directs
design within the user's goal and constraints, chooses among routine alternatives,
requests revisions, and accepts actual content revisions. Read live state and
relevant intent; keep concise progress rather than inheriting worker discussion.
The manager loads the lifecycle procedure; schema owns artifact criteria and
SpecD owns lifecycle state. You do not issue human-only CLI spec/signoff approvals.

Before proposal authoring establish the participation choice through the design
manager. If delegation begins later, hand the unfinished scope and existing draft
to a separate executor before acceptance. That executor independently reads inputs
and verifies/revises the content, taking author responsibility. Preserve completed
scopes. Your identity must differ from the author of the revision you accept.

Launch one scoped executor and separate manager with exact resource/source
pointers and the current goal/constraints, without inherited conversation. Give
the executor its bounded assignment and criteria before authoring. Use separate
arbiters at the manager's three triggers: first draft, your content acceptance,
or explicit request. For corrections within a review keep that arbiter; routine
comments alone launch none. Workers use their own source reads and communicate
concise results. Schedule roles within available client slots; if the client lacks
independent contexts save continuation and report the limitation. An idle manager
may yield a slot and resume from scoped pointers; do not impersonate it.

Read the returned concrete revision/merged result against criteria and user
constraints, resolve routine ambiguity, and explicitly record acceptance of its
revision in change-local `.context`. Mode selection and an arbiter's success are
not acceptance. Trigger final independent review; any resulting content change
returns to you for acceptance before validation/subscope closure. Actual acceptance
and final success must match that revision, including no-op and optional artifacts.
Conflicts with earlier approved inputs return affected content to review; reconsider
dependent scopes and keep unrelated completed scopes closed.

Complexity governs lifetimes in delegated mode too. Small design may keep one
executor/manager through plan. Large design launches a fresh group per artifact
and system overview/subsystem scope, with separate author contexts and focused
inputs. The main coordinator persists. Use the staged system procedure; no
incomplete system or downstream validate/plan is structurally validated/authored.
After matching acceptance/review, have the executor perform applicable CLI
validation/hooks and save continuation; stop active workers before the next group.

Return to the real user only for missing information or authority outside the
provided goal/constraints or a human-only CLI gate. Stop there with the exact
required input/command. When design reaches its terminal boundary, report the
result and unresolved matters concisely and suggest the next skill. Design
participation delegates acceptance through plan, not automatic implementation,
verification, or archive. Do not invoke the next lifecycle skill without a user
request.
